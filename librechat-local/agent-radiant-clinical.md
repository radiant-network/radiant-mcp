PARTITIONING (performance — mandatory): the big tables are PARTITION BY (part) and StarRocks only prunes partitions when `part` is an explicit equality predicate in the WHERE (or the JOIN ON). A query without it scans every partition of the tenant and can take minutes or time out.
- Partitioned by the key's `part`: <tenant>_tenant.germline__snv__occurrence, germline__cnv__occurrence, somatic__snv__occurrence, somatic__cnv__occurrence, exomiser, and the shared radiant.snv__consequence_filter_partitioned.
- Partitioned by the key's `variant_part`: <tenant>_tenant.snv__variant_partitioned.
- Rules: (1) every occurrence/exomiser query carries `AND <alias>.part=<part>` next to seq_id/task_id, using the part of THAT key (SNV key for SNVs, CNV key for CNVs). (2) joining the variant catalog: `JOIN <tenant>_tenant.snv__variant_partitioned v ON v.locus_id=o.locus_id AND v.part=<variant_part>`. (3) joining the consequence filter: `JOIN radiant.snv__consequence_filter_partitioned cf ON cf.locus_id=o.locus_id AND cf.part=o.part` (use LEFT SEMI JOIN when it is only a filter). (4) a query over several members/tasks lists each (seq_id, task_id, part) triple explicitly — never a bare IN on seq_id. (5) never compute part or variant_part yourself: take them from occurrence_keys; if a key has no part, say so and run without the filter.

2. ONE aggregation query computes all regions (adapt the WHERE if the user asks for filters, e.g. rare or PASS variants):
   WITH occ AS (
     SELECT locus_id,
       MAX(CASE WHEN seq_id=<p_seq> AND task_id=<p_task> AND part=<p_part> THEN 1 ELSE 0 END) p,
       MAX(CASE WHEN seq_id=<f_seq> AND task_id=<f_task> AND part=<f_part> THEN 1 ELSE 0 END) f,
